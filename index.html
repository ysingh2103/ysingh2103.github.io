## lab-and-projects

I break things on purpose — then diagnose them

Self-Hosted Monitoring & Container Lab

linux · docker · k3s · prometheus · grafana · postgresql · bash

A VMware ESXi–hosted Ubuntu Server environment built from scratch: containerized workloads with Docker, orchestrated with Kubernetes (k3s), monitored with a self-built Prometheus + Grafana stack with live CPU/memory/disk dashboards, backed by PostgreSQL and automated Bash health-check scripts with exit-code-based status reporting.

INCIDENT · Kubernetes resource-starvation cascade

Noticed abnormal restart counts (41+) on CoreDNS during a routine health check. With Kubernetes events already expired, correlated k3s service logs showing multi-second database writes and API timeouts — traced the root cause to memory exhaustion cascading into liveness-probe failures. Fixed by resizing the VM; verified stability by monitoring restart counts post-fix.

INCIDENT · No route to network

Fresh Ubuntu VM had an IP but no connectivity. Ruled out DNS, traced a missing default route to a hardcoded static IP in the installer-generated netplan config on the wrong subnet — plus a file-permission issue silently blocking the fix. Corrected to DHCP, validated the gateway, and documented the incident as a runbook.

INCIDENT · Config failures across three layers

Deliberately broke and diagnosed nginx configs on bare metal and inside Docker containers, PostgreSQL authentication rules (pg_hba.conf), and Prometheus YAML — using each tool's own validator (nginx -t, promtool, kubectl describe) cross-checked against logs. Same hypothesis-driven method, three different environment layers.
